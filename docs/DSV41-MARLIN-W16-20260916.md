## Findings

1. **Correctness of the resident experts.** The CUTLASS MXFP8xMXFP4 kernel the tree
   picks for MXFP4 experts on SM120 returns outlier tokens 6–12% short (found on
   V4-Flash the same morning, see the V4-Flash note). V4.1's hot-7 ran on it since
   09-13. Marlin (W4A16) checked against the checkpoint tensors of the placed
   logical experts (`KT_HOT_CHECK=1`): rel 0.39%, norm ratio 1.002 (layer 0,
   physical 0..2 = logical 292/60/179). The streamed groups in W16 mode: rel 0.29%.
2. **Arena pinning.** With 336 GB of arenas, the load fragments memory (the
   checkpoint's page cache fills it first) and a third of the arenas end up on 4K
   pages (`shmem_huge` 218 of 325 GB). `cudaHostRegister` of a 4K-page layer is
   100x slower than a huge-page one: layers 0–25 0.2 s, 26–37 1–3 s, layer 38 96 s,
   layer 39 58 s — the first request paid 500 s. Pinning at load time hides it in
   the startup (25 s for rank 0; rank 1 waits on rank 0's fd exchange). Setting
   `/sys/kernel/mm/transparent_hugepage/defrag` to `madvise` raised the huge share to
   74% but did not remove the 4K tail. `swapoff -a` was needed first: with the
   arenas mbind'ed per node, node 1 running out of free memory made the kernel
   swap instead of dropping page cache, and memguard killed the server at 6 GB
   of swap (avail memory was 158 GB at the time).
3. **VRAM.** hot-7 Marlin + streamer + 1M pool left 0.5 GB and OOMed at 22K
   context (the attention scratch grows with context). hot-5 frees ~0.7 GB;
   decode is unchanged at 34 (the last two hot experts bought nothing
   measurable). G=16 did not fit at all (bf16 group buffer 35 MB/expert).
   The streamer's CUTLASS workspace is sized for the prefill chunk on its first
   allocation — a second, larger one on a later chunk size cannot free the first
   (captured graphs hold it) and OOMed once.
4. **Chunking.** With radix off the SWA pool is capped at one request's window
   (5120 tokens) and the scheduler alternates 2048/768/1792-token chunks; the
   streamed prefill costs ~7.5 s per chunk regardless of size. `--swa-prefix-tails 6`
   (cap 7424, ~1 GB of VRAM per rank as SWA slots carry the c4 state) makes every
   chunk 2048: 37 → 24 chunks, 283 → 198 s.
5. The V4.1 harness had the same `curl -d "$body"` argument-length failure on
   48K prompts as the V4-Flash one; fixed (body via file).

## Open

* The 4K-page tail of the arenas: drop the checkpoint page cache right after the
  load, or reserve hugetlb pages for the arenas, would make the pinning ~8 s.
* Per-layer 185 ms is 377 experts x 8.8 MB / 9.5 GB/s — PCIe-bound like V4-Flash.
